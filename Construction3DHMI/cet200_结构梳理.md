# cet200 结构梳理

> 梳理对象：`WorkOS/02_Projects/Self_Care_Freestyle/Construction3DHMI/cet200`
> 来源：VMT（VMC Motion Technologies Co., Ltd.）开源仓库，Apache-2.0
> 标注约定：**【事实】**= 文件/代码可直接验证；**【推断】**= 基于事实的合理推测，未做运行验证。

## 一句话结论

cet200 是一套**面向物理仿真（AGX Dynamics）的 20t 级虚构液压挖掘机模型资产包**，核心价值在于它把「CAD → 通用 3D 格式 → URDF → 物理引擎装配」这条链路完整打通，并且给出了**一套带明确工程参数的整机规格（质量分解、油缸尺寸、推力/速度、回转/行走能力）**。
对 Construction3DHMI 而言，可直接复用的是 `exchange_formats/parts/*.glb`（米制、分部件、link-local 坐标），以及 `cet200.xacro` 里那张现成的**关节层级 + 原点/轴向表**——二者合起来就是驱动挖掘机三维动画所需的最小数据集。

## 2. 资产转换管线【事实】

```
spaceclaim_momentum/cet200.scdoc   ← 唯一源头（SpaceClaim 2024 R2 + Algoryx Momentum 2.8.1）
        │
        ├─→ agx_file/cet200.agx                  （AGX 场景，二进制）
        ├─→ exchange_formats/cet200.glb / .stp   （整机交换）
        └─→ exchange_formats/parts/*.glb         （分部件）
                    │
                    │  Blender 4.2 后台重转（tools/run_blender_convert_glb_to_dae.bat）
                    ↓
            cet200_description/meshes/*.dae      （URDF 用 Collada）
                    │
                    │  xacro（colcon build 时自动执行）
                    ↓
            cet200_description/urdf/cet200.urdf
```

两个值得记住的细节：
1. **为什么要 Blender 中转**：SpaceClaim 直接导出的 glb 会带黑线，所以用 Blender 4.2 重新导入再导出（先 glb→glb 洗一遍，再 glb→dae）。
2. **URDF 是生成物**：`urdf/CMakeLists.txt` 里用 `add_custom_command` 调 xacro 生成，文件头明确写了 "EDITING THIS FILE BY HAND IS NOT RECOMMENDED"。要改模型改 xacro。

## 3. 命名规则（贯穿全项目）

| 前缀 | 含义 | 在 AGX 中的处理 |
|---|---|---|
| `RB_*` | 真实刚体（RigidBody），带质量/惯量 | 直接作为刚体参与仿真 |
| `TF_*` | 纯坐标参考点（ObserverFrame），无质量 | `cet200_compare_models.py` 读取 URDF 时把 `TF_*` link 转成 AGX ObserverFrame |
| `Dummy_*` | 辅助/占位对象（固定副、纯视觉） | 读入后**主动删除**（`TF_*`、`Dummy_*` link 与 `Dummy_LockJoint_*` 约束全部移除） |

这套「用 Dummy/TF 在 URDF 里承载坐标系，再由加载器翻译成引擎内的参考系」的做法，是把 ROS 描述文件复用到非 ROS 引擎的通用手段，值得借鉴。

## 4. cet200_description：URDF/Xacro 结构

### 4.1 关节-连杆树【事实】

```
TF_Origin
 └─(fixed) RB_TrackFrame           3800 kg    [履带架/下车]
     ├─(fixed) base_link           ← 哑元，对应 AGX 的 ObserverFrame
     ├─(Hinge_Slew, z轴, continuous) RB_UpperStructure   7600 kg  [上车/回转平台]
     │    └─(Hinge_Boom, y轴, revolute) RB_Boom          1440 kg
     │         └─(Hinge_Arm, y轴, revolute) RB_Arm        950 kg
     │              └─(Hinge_Bucket, y轴, revolute) RB_Bucket  700 kg
     ├─ Hinge_Sprocket_L/R  → RB_Sprocket_L/R   340 kg ×2
     ├─ Hinge_Idler_L/R     → RB_Idler_L/R      108 kg ×2
     ├─ Hinge_Roller_L1..9 / R1..9 → RB_Roller_*   35 kg ×18
     ├─(fixed) Dummy_RB_CrawlerBelt_L/R          纯视觉履带外壳
     └─(fixed, 装在上车) TF_LidarBase             (1.17928, 0.9, 2.10413), rpy 0 π/4 0
```

- 坐标系：**Z-up**，工作装置朝 **+X**，左右为 **±Y**（左右履带 y = ±1.1），回转绕 Z。
- 驱动轮/导向轮：x = ∓1.6872，z = 0.38945；上滚轮 2 个（z=0.71245），下滚轮 7 个（z=0.18295）——与规格表「上ローラ2 / 下ローラ7（片側）」一致。
- 右侧驱动轮的 mesh 需要 `rpy = π, 0.0305, 0` 翻转 → **左右件是镜像实例**，做 HMI 时不要假设左右完全对称。

### 4.2 关节限位与能力【事实】

| 关节 | 类型 | 行程 (rad) | effort (N·m/rad) | velocity (rad/s) |
|---|---|---|---|---|
| Hinge_Slew | continuous | — | 70000 | 1.256637 |
| Hinge_Boom | revolute | -0.443 ~ 1.127 | 2,009,946 | 0.648409 |
| Hinge_Arm | revolute | -1.40 ~ 0.648 | 300,268 | 0.597574 |
| Hinge_Bucket | revolute | -1.236 ~ 1.77 | 253,122 | 0.706018 |
| Hinge_Sprocket | continuous | — | 38437（单侧牵引扭矩） | 4.074104 |

### 4.3 AGX 模型比 URDF 多了什么【推断，依据代码可验证部分为事实】

- AGX 模型里同时存在 `Prismatic_Boom/Arm/Bucket`（**液压缸的棱柱副**）和 `Hinge_Boom/Arm/Bucket`（铰点）；`excavator_monitor.py` 把这两组 9 个关节全部列为监控对象。
- URDF 里**只有 Hinge_Boom/Arm/Bucket**，没有缸筒/活塞杆 link（规格表里却有 `RB_BoomCylinderTube` 等质量条目）。
- 结论：URDF 是**运动学近似版**（用等效铰接力矩代替油缸驱动），AGX 模型是**含液压油缸的机构完整版**。`cet200_compare_models.py` 就是用来把这两个版本并排放一起对比的。

## 5. cet200_agxpy_standalone：仿真程序

### 5.1 模块职责

| 文件 | 职责 |
|---|---|
| `cet200.py` | 核心装配：加载 .agx、挂履带、建 ObserverFrame、回转制动、挖掘铲斗（Shovel）设置、材质/摩擦 |
| `apps/cet200_on_ground.py` | 平地（静态 Box 地面）行走 + 动作，带键盘/手柄与监控 |
| `apps/cet200_on_terrain.py` | 土壤地形（agxTerrain）+ 真实挖掘，监控输出挖掘阻力与斗内土量 |
| `apps/cet200_compare_models.py` | URDF 模型 vs AGX 模型并排对照（关闭两者间碰撞） |
| `excavator_keyboard_gamepad.py` | 键盘 / XInput 手柄输入 → 关节速度指令 |
| `excavator_monitor.py` | 屏幕 HUD：关节角度/速度/力矩 + 挖掘各分力 |

### 5.2 三个 app 的差异

| 场景 | 地面 | 地形 | Shovel 挖掘 | 控制 | 自动步进 |
|---|---|---|---|---|---|
| on_ground | Box(10,10,1) | — | 无 | 键盘+手柄 | True |
| on_terrain | — | 200×200格, 0.15m, 深2m, dirt_1 | 有（5 齿） | 键盘+手柄 | True |
| compare_models | Box(20,20,1) | — | 无 | 无（只开电机） | False |

### 5.3 履带系统关键参数【事实】

`Track(46, 0.6, 0.135, 0.000499592)`：46 节/侧、宽 0.6 m、高 0.135 m、初始张力 4.996e-4。履带节点质量 34 kg（与规格表「リンクシュー質量 34」一致）。

调过的稳定性参数：hinge compliance 1e-9、hinge damping 2/60、最小稳定法向力 9e4 N、铰链范围 -75°~+20°、节点合并（2 节/段、接触缩减 MODERATE）。

摩擦：地面-履带用 `ConstantNormalForceOrientedBoxFrictionModel`，法向力 = 20186 × g / 40（约 4.9 kN/节点，40 为假设的接地节点数）；主方向摩擦系数 1.0，副方向 0.25。

### 5.4 操作映射

| 动作 | 键盘 | 手柄（XInput） |
|---|---|---|
| 回转 | a / s | 左摇杆 左右 |
| 斗杆 | z / x | 左摇杆 上下 |
| 铲斗（挖掘/卸料） | j / k | 右摇杆 左右 |
| 动臂 | m / , | 右摇杆 上下 |
| 左履带前进/后退 | ←→ 转向 | LB / LT |
| 右履带前进/后退 | ↑↓ 行走 | RB / RT |

摇杆死区 0.3，键盘油门固定 0.6。回转在「目标速度≈0 且当前速度≈0」时自动切换为 LockController 抱闸，制动力矩为电机力矩的 **4 倍**（`HINGE_SLEW_BRAKE_MULTIPLIER = 4`）。

### 5.5 监控输出内容

- 9 个关节的 Angle / Speed / Force(kN)
- 挖掘力分解：Penetration / SeparationContact / Contact / DeformationContact / **Total**（kN，含 xyz 分量）
- 斗内土体体积 (m³) 与质量 (kg)

这套 HUD 输出对「力反馈型 HMI / 操作辅助显示」是现成的指标清单。

## 6. openplx（WIP）—— 值得注意的趋势信号

`cet200.openplx` 用声明式语法重写了 `cet200.py` 的装配逻辑（履带、地面、接触材质、场景）。**【推断】** 这代表厂商在把「代码装配」往「数据描述」迁移。
当前未完成处（文件内自带注释）：副方向摩擦系数未实现（`How do I set SECONDARY_DIRECTION?`），法向力写法 `20186 * 0.5` 与 Python 版的 `20186*g/40` 不等价 → **不要拿它当基准**。

## 8. 运行方式

**方式 A：Python 直跑（Windows/Linux）**
```
git clone <REPO> && cd cet200/cet200_agxpy_standalone
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt        # 实际就是 -e .
cd src/cet200_agxpy_standalone/apps
python cet200_on_terrain.py
```

**方式 B：ROS2（Ubuntu 22.04 + Humble）**
```
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
ros2 run cet200_agxpy_standalone cet200_on_terrain
ros2 launch cet200_description display.launch.py     # RViz 看 URDF
```

依赖门槛：AGX Dynamics ≥ 2.40.1.5 且需 **Core / Tracks / Terrain / Granular** 四个 License 模块（商业授权）；Python ≥ 3.9.9。

一个工程细节：三个 app 的 `main()` 都先做 `sys.argv[0] = Path(__file__).resolve()`——因为 colcon 会把 console_scripts 名字塞进 argv[0]，而 AGX 要按这个路径找模型文件。这类「框架注入参数破坏第三方库假设」的坑很典型。

## 9. 与 Construction3DHMI 的结合点（按优先级）

| ⭐ | 可用资产 | 怎么用 |
|---|---|---|
| ⭐⭐⭐ | `exchange_formats/parts/*.glb`（12 个分部件，米制） | Assimp 直接加载，按部件独立摆放 → 可做关节级动画，而非只能整体旋转 |
| ⭐⭐⭐ | `cet200.xacro` 的 joint origin/axis/limit 表 | 现成的骨骼层级与变换数据，直接喂给场景图；limit 可直接做动画限位 |
| ⭐⭐ | `docs/cet200_spec.xlsx` 的油缸行程/速度/推力 | 给 HMI 的「虚拟仪表 / 动作节拍」提供物理合理的数值，而不是拍脑袋插值 |
| ⭐⭐ | `excavator_monitor.py` 的指标清单 | 挖掘阻力分解 + 斗内土量 → HMI 该显示什么的现成范式 |
| ⭐ | `exchange_formats/cet200.glb` / `.stp` | 只要静态整机外观时的最简路径 |
| ⭐ | `docs/cet200_excavation.gif` | 视觉参考 |

**需要注意的两点【推断，待验证】**
1. parts/*.glb 与 URDF link 的坐标原点是否严格对齐：URDF 中 visual 的 origin 基本为 0，且 dae 正由这些 glb 转换而来 → 推断部件 glb 顶点已是 **link-local 坐标**，加载到 joint frame 即可，无需额外偏移。正式使用前建议用 Assimp 载入一个部件核对包围盒。
2. glb 是 Z-up 米制（与 URDF/AGX 一致），若 HMI 侧使用 Y-up 约定需在加载时统一。

## 10. 注意事项

- **机型是虚构的**（README 明确 "A fictional 20-ton-class hydraulic excavator"），参数可用于方法验证与量级参考，**不可当作徐工真实机型对标数据**。
- `cet200.urdf` 是 xacro 生成物，禁止手改。
- `agx_file/*.agx` 为二进制，脱离 AGX 环境无法查看；不要指望从它反推结构。
- `openplx/` 是 WIP，存在未完成项（见 §6）。
